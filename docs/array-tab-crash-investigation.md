# Array 탭 클릭 종료 문제: 재현과 수정

## 직접 재현한 원인

복잡한 구조체를 다시 탐색해서 발생하는 문제가 아니라, **포인터 이름에 포함된
밑줄(`_`)과 공통 마우스 이벤트 처리의 조합**에서 예외가 발생했다.

1. 기존 탭은 포인터 이름을 WPF `Button.Content` 문자열로 표시했다.
2. 기본 버튼 템플릿의 `AccessText`는 `raw_buffer` 같은 문자열의 밑줄을
   단축키 표시로 해석하고 내부에 `Run` 텍스트 요소를 생성한다.
3. 글자 위를 누르면 `PreviewMouseDown.OriginalSource`가 `Run`일 수 있다.
4. 자동완성 팝업을 닫는 공통 핸들러가 그 요소를 `Visual.IsAncestorOf`에 넘겼다.
5. `Run`은 `Visual`이 아니므로 다음 예외가 발생했다.

```text
System.InvalidOperationException:
'System.Windows.Documents.Run' is not a Visual or Visual3D.
  Visual.IsAncestorOf
  SensorImageViewerControl.DismissExpressionSuggestionsOutside
```

이 이벤트는 탭의 `Click`보다 먼저 실행된다. 따라서 탭 전환의 예외 처리와
`array-tab` 로그 생성에 도달하지 않는다. 이미 선택된 탭을 다시 클릭하거나
디버깅을 종료한 후 클릭해도 동일한 경로를 지난다.

실제 확장 컨트롤을 사용하는 독립 WPF 테스트 호스트에서 `InputHitTest`로
`Run`을 찾고 그 요소에서 마우스 이벤트를 전달해 수정 전 예외를 재현했다.
이는 실제 Visual Studio 프로세스에서 종료를 재현하거나 문제 PC의 덤프를
분석한 것과는 구분해야 한다.

## 수정

- 공통 마우스 핸들러가 `ContentElement`와 `Visual`의 부모를 각각 안전하게 찾는다.
- 포인터 탭 이름은 단축키가 아닌 일반 `TextBlock`으로 표시한다. 밑줄을 보존하고
  접근성 이름도 제공한다.
- 탭 전환과 캡처 시 기존 탭 버튼을 유지한다. 선택 스타일과 제목만 갱신하며,
  새 탭 추가/삭제 시 해당 헤더만 추가/제거한다.
- 현재 탭을 다시 누르면 전환 정리 작업도 실행하지 않는다.
- 디버거 실행/종료 시 이전 메모리 읽기와 예약 갱신을 취소한다. 실행 중인
  하드웨어 감시 자체는 유지하며, 취소된 감시 재시도 이벤트는 무시한다.
- 별도 감시 점검에서는 중단점이 사라진 뒤 새 사용자 중단점을 우리 것으로
  잘못 채택할 수 있는 문제도 수정했다. 소유권은 주소와 기존 목록을 확인해
  결정하고, 한번 확인한 중단점의 식별자를 다른 대상으로 바꾸지 않는다.
  식별자가 바뀌었는데 같은 주소가 남아 있으면 삭제 성공으로 간주하지 않고
  소유권을 확인할 수 없다는 오류를 반환한다.

## 검증

`tests/ViewerWorkspacePreview/run.ps1 -Verify`는 다음 항목을 검사한다.

- 밑줄이 있는 버튼의 글자를 대상으로 한 실제 WPF 히트 테스트와 마우스 이벤트 경로
- 이미 선택된 탭 반복 클릭 시 상태와 타이머 보존
- `UInt16` 및 구조체 멤버 표현식 설정을 가진 탭의 추가, 12회 왕복, 닫기
- 전환 중 버튼 객체/키보드 포커스 보존 및 밑줄의 문자 그대로 표시
- 캐시 복원 시 새 디버거 메모리 읽기 없음
- 디버거 실행/종료 시 이전 예약 작업과 렌더 결과 무효화
- 취소된 감시 재시도 이벤트가 중단점 작업을 수행하지 않음

`tests/OptionsPagePreview/run.ps1`의 중단점 테스트는 가짜 자동화 객체로
사라진 중단점, 중복 주소, 새 사용자 중단점, 지연된 등록, 불완전한 목록을
검사한다. 실제 VS 네이티브 디버거의 COM 공급자를 실행한 검증은 아니므로,
공급자가 주소/식별자를 다른 형태로 제공하는 경우에는 수동 검증이 필요하다.
소유권을 확인할 수 없는 경우 다른 중단점을 추측해 삭제하지 않는다.

## VS 2022 설치 후 확인할 항목

1. `input_buffer` 또는 `(this->buffer.C).m_data`처럼 밑줄이 있는 포인터를 캡처한다.
2. 탭의 빈 여백뿐 아니라 **이름의 글자 위**를 여러 번 클릭한다.
3. `+ Array`로 탭을 추가한 뒤 기존 탭과 새 탭을 반복해서 전환한다.
4. 디버깅을 종료한 뒤에도 캐시가 있는 탭을 클릭한다.
5. 별도로 Watch를 걸고 F5/F10 및 디버깅 종료를 확인한다. Watch가 실행 중에는
   유지되고, 취소된 이전 예약 작업이 새 탭이나 다음 세션에 적용되지 않아야 한다.

독립 WPF 회귀 테스트만으로 모든 VS 확장/테마/네이티브 디버거 조합의 안정성을
보장할 수는 없다. 실제 문제가 발생한 PC에서 위 설치 후 검증이 필요하다.
