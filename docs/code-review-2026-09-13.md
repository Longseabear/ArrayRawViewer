# 코드 점검 및 수정 — 2026-09-13

## 반영한 변경

- 큰 통계 계산에 취소 토큰을 전달한다. 프레임/범위 변경, Stats 닫기, 읽기 요청 변경 시 이전 계산을 취소하고 최대 1,024샘플 간격으로 취소를 확인한다. 이전에는 결과만 버리고 계산은 끝까지 실행했다.
- 구조체 검색 결과의 `Use captured object`는 별도의 바인딩 루트를 사용한다. SEARCH ROOT의 `this`는 유지되어 다음 검색도 같은 부모 객체에서 시작한다.
- 중첩된 템플릿 필드 적용에서 이벤트 억제 상태를 보존한다.
- 정수형 고정 배열을 구조체 탐색에서 제외한다. 등록된 구조체 배열은 계속 탐색한다.
- 탭마다 실제 선택 X/Y를 저장한다. 입력이 `centerX` 같은 식이어도 이전 탭의 좌표를 가져오지 않는다.
- Watch의 바이트 범위 끝까지 주소 오버플로를 확인하고, 지원되지 않는 원소 크기와 잘못된 좌표를 거부한다.
- 같은 Watch 재사용 조건에 원소 크기를 포함한다.
- Clear, 탭 전환 및 새 Watch 요청에서 기존 대기 요청을 취소한다. 대기 중 변경된 포인터에 이전 요청이 적용되는 것을 방지한다.

## 이전 Watch 설명 정정

0.11.51 이전 코드는 괄호가 포함된 식을 숫자 주소로 해석한 뒤, 원소 오프셋을 그 숫자에 직접 더했다. 포인터 타입이 없어진 숫자 덧셈에는 원소 크기가 적용되지 않는다. `uint*`, stride=96, (5,5)는 485원소, 즉 1,940바이트 오프셋이다. 이 회귀 사례를 테스트에 추가했다. 이전에 설명한 지연 바인딩 타이밍은 직접 검증한 원인이 아니다.

## 검증

- C# 코어 테스트 통과: 통계 취소, 정수 배열 검색 제외, (5,5) Watch 주소, 주소 범위 오버플로 포함.
- VS2022 MSBuild에서 기본 확장 및 VS2015 호환 프로젝트 컴파일 통과.
- VS2015 실제 IDE 실행과 Visual Studio UI 통합 시나리오는 이번 점검에서 실행하지 않았다.

## 후속 점검 대상

- 네이티브 중단점 소유권 탐색은 이름/컬렉션 순서에 의존하는 경로가 남아 있다. 같은 주소의 사용자 중단점과 Viewer 중단점을 함께 만든 환경에서 생성·해제 테스트가 필요하다.
- 구조체 검색 캐시는 동일 중단 상태에서 스택 프레임만 바뀌는 경우를 구분하지 않는다. 프레임 식별자를 캐시 키에 포함하는 후속 개선이 필요하다.
- 오래된 Visual Studio SDK의 Threading/Newtonsoft 참조 버전 충돌 경고가 남아 있다. VS2015 런타임 호환성 검증과 함께 의존성을 정리해야 한다.

## 수동 회귀 확인

1. SEARCH ROOT=this → Search objects → output 선택 → Use captured object 후에도 SEARCH ROOT=this인지 확인한다.
2. 두 탭에서 서로 다른 좌표를 선택하고 X/Y를 변수식으로 유지한다. 탭 왕복 시 각 탭의 선택 좌표를 확인한다.
3. 큰 Loaded ROI 통계를 켜고 범위를 빠르게 바꾸거나 Stats를 닫는다. 이전 계산의 CPU 작업이 중단되는지 확인한다.
4. Watch 해제 대기 중 다른 탭으로 이동한다. 자동 Continue나 새 Watch가 발생하지 않아야 한다.
5. ImageSimulator 처리 전 output을 바인딩하고 (5,5)를 Watch한다. 쓰기 직후 중단 및 Watch Next X/Y와 자동 해제를 확인한다.
